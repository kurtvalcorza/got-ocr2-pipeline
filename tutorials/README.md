## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) recognised the synthetic printed page and reported `sample-sanity` error rates against its rendered transcript. This notebook keeps that page and its inference contract as Section 5 and adds the adaptation contract around it: a real labelled line set fetched with per-row-group pins, a corpus-level protocol in the carried `metrics.py` (uncapped micro and macro CER / WER, exact match, hypothesis length) with two non-adapted baselines, a bounded fine-tuning with the model's own objective on cached frozen-prefix states, line panels, the page re-read after adaptation, and an artifact that reloads. The per-image `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`). The pipeline now loads in float32 on every device (the inference-only notebook used bfloat16 on CUDA), batches generation, and admits text lines wider than 4,096 px.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's three modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh runtime lacks, at the pinned revision (never `main`); `verify_snapshot` re-hashes every entry and asserts the pinned `model.safetensors` digest and byte count before the processor or the model is constructed; `GotOcr2Pipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`) in float32 and picks CUDA when it is visible. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `pyarrow`, `urllib`, `torch.optim` or the model's processor directly.
- **Data (DAT1–DAT9, ST6):** the default sample is the Belfort-line dataset (`Teklia/Belfort-line` at the immutable parquet-conversion revision `c4a74bbd39f2df314752e7e6026649a39d365cbb`, MIT): the first eight row groups of `default/test/0000.parquet` read with HTTPS range requests in the carried `samples.py` (the shard's declared size and row count checked first, each row group refused unless its SHA-256 and byte total match `ROW_GROUP_PINS`; about 44 MB), and `read_corpus` makes each row a record with its 128-px line image and its transcript (whitespace runs collapsed); `build_sample_dataset(seed=SPLIT_SEED)` draws 600 / 60 / 140 and `check_split_disjoint` asserts no image (by decoded-pixel digest) is shared. The template adds a second *External access* bullet naming the host, the revision, the byte count and the licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` per split + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` + `recognize` with sanity checks + `evaluation_report` on the synthetic page (inference contract) → `empty_baseline` + `constant_baseline` + `pipe.evaluate` on the frozen model with four hypotheses printed (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison, the transcript breakdown and the per-measure `beats` record (evaluation) → the line panels + `recognize` + `evaluation_report` on the page again (inference) → `pipe.save_artifact` → `GotOcr2Pipeline.from_artifact` with the parity check (export and reload). Sections 5, 6 and 7 call `reset_to_pretrained()` first, so a re-run never reads a *frozen* number from the adapted model, and `GotOcr2Pipeline.adapt` refuses an already adapted pipeline (review GOT-M5).
- **Score semantics (UNC1–UNC4):** generated text carries no score, no probability and no correctness signal, and the notebook says so before the first recognition; the corpus rates are uncapped Levenshtein rates over one crowdsourced transcription at stated normalisations, with the hypothesis length beside them so a rate above 1.0 is read as over-generation; no acceptance threshold ships. The page re-read after adaptation carries a `sample-sanity` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the empty string, the constant transcript and the frozen model are scored on the same 140 lines as the adapted model, on the same rates; every metric is labelled as one seeded split of one sample with no dispersion estimate, and the notebook says explicitly that the frozen model sits below the empty baseline (it invents text), that the gain is measured on one French council's cursive only, and — per measure — that the adapted CER beats both baselines while the adapted WER (1.017 in the T4 record) does not beat the empty (1.000) or the constant (0.999) baseline (review GOT-M4: `adapted_cer_beats_both_baselines` and `adapted_wer_beats_both_baselines` replace a flag that was named for both baselines but computed on CER only).
- **Split integrity (SPL1–SPL10):** the split is seeded and image-disjoint; validation (60 lines) selects the epoch on CER and the test split is used for nothing but the final evaluation. The split unit is the line image: Belfort-line's parquet has only `image` and `text`, so a page- or writer-disjoint split is impossible, and the shard is not in page order (neighbouring lines name years far apart and their widths are uncorrelated, r = 0.02), so runs of consecutive lines are no page proxy either and a test line's shard neighbour in training says nothing about its page (review GOT-M3; the same split as the Florence-2 sibling row). The notebook states the independence assumption (a same-collection estimate, likely optimistic for a new register or hand), counts the validation and test transcripts that also occur verbatim in training (2 and 5 at the default seed) and reports the held-out rates without them (T4 record's per-line hypotheses: adapted CER 0.759 on all 140 lines, 0.764 on the 135 with an unseen transcript).
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (16384), `MAX_IMAGE_PIXELS` (4096²), `MAX_NEW_TOKENS` (4096), `DEFAULT_MAX_NEW_TOKENS` (1024), `DEFAULT_LINE_MAX_NEW_TOKENS` (128), the two `MODES`, `DECODING`, `STOP_STRING`, the record bounds (8..5,000 for training; a BYOD dataset needs at least 12 distinct images), `MAX_TEXT_CHARS` (512) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is taken from the upload dialog (Colab) or from `BYOD_PATH` (any runtime; a folder works too), an empty or cancelled upload stops with a message naming the next action, the zip is read member by member (names flattened, no `extractall`; two files with one name are refused) or a directory walked, pixel-duplicate images are counted and named before the split, the split must leave at least 8 training, 2 validation and 2 test lines (at least 12 distinct images; the refusal names the split), each row of `transcripts.csv` becomes a record, and the records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells. The expected layout and the privacy guidance are stated in the Prerequisites and in Section 4, and the training split's summary is written to `outputs/got_ocr2_train.csv`.
- Licence: the weights are Apache-2.0 and the notebook, README, card and `docs/WEIGHTS.md` say so; Belfort-line is MIT and is not redistributed — the export records the corpus name, repository, revision, file, licence, language and row groups under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
