# Weight provenance and DIMER hosting

- Upstream: `stepfun-ai/GOT-OCR-2.0-hf`
- Immutable revision: `d3017ef2c2c1395888c8d635c5e0508bcb0ac78d` (the Hub's `main` resolved to this commit on 2026-09-14)
- Weight format: SafeTensors (`model.safetensors`, 1,121,114,488 bytes, bfloat16 tensors); the upstream repository hosts no pickle checkpoint at this revision.
- Manifest: `weights/got-ocr-2.0-hf/dimer-base-manifest.json` (8 files: `README.md`, `config.json`, `generation_config.json`, `model.safetensors`, `preprocessor_config.json`, `special_tokens_map.json`, `tokenizer.json`, `tokenizer_config.json`; 1,139,869,676 bytes total, per-file SHA-256)
- Upstream weight license: Apache-2.0 (the checkpoint's `README.md` front matter and the Hub's licence tag)
- DIMER hosting: Apache-2.0 permits use, modification, distribution, and commercial use subject to preservation of the licence and notices. The Git repository does not vendor the checkpoint (`weights/**/*.safetensors` is git-ignored) **nor the 18.7 MB `tokenizer.json`** (git-ignored in this repository only; it is manifest-listed and staged with the weights); DIMER may mirror the pinned snapshot in its model store under the upstream license.
- Fresh clone: `stage_missing_files(allow_download=True)` fetches only the manifest-listed files absent on disk (here `model.safetensors` and `tokenizer.json`), at the pinned revision, into the snapshot directory; `verify_snapshot()` then checks every file before any load. `weights/**` is marked `-text` in `.gitattributes` so Windows `core.autocrlf` cannot rewrite the committed small files and break their digests.
- Loader trust boundary: Transformers `AutoModelForImageTextToText` (`GotOcr2ForConditionalGeneration`) / `AutoProcessor` (`GotOcr2Processor`, the slow image processor the snapshot declares, and the Qwen2 tokenizer) with `trust_remote_code=False`, `local_files_only=True` from the verified directory; nothing is fetched at construction or inference (the smoke run loaded and recognised with `HF_HUB_OFFLINE=1`). The model is loaded in float32 on every device (the checkpoint's bfloat16 tensors are upcast at load, so the adapter trained in float32 overlays without a cast); generation passes `stop_strings="<|im_end|>"` with the processor's tokenizer, as the pinned README's examples do, and the vision tower runs one image per forward (`VISION_BATCH_SIZE = 1`) because its eager attention over 4,096 patch tokens needs about 0.8 GB per image per global layer.
- Adapter artifacts: `save_artifact` writes the trained tensors (the last four decoder layers and the final norm, 49 tensors, about 206 MB in float32) as `adapter.safetensors` beside a `manifest.json` (`org.valcorza.got-ocr-2.0-hf.adapter.v1`) naming the base model id and revision, the base `model.safetensors` SHA-256, the tensor names, the file size and SHA-256, the training configuration and the epoch history. `from_artifact` re-verifies the base snapshot and checks the manifest, the digest and the exact tensor set before deserialising; an adapter is derived from the lines it was trained on and is not redistributed by this repository.
- Adaptation sample: `Teklia/Belfort-line` (MIT), parquet-conversion revision `c4a74bbd39f2df314752e7e6026649a39d365cbb`, `default/test/0000.parquet` row groups 0–7 (800 lines, about 44 MB) read over HTTPS range requests, each row group pinned by SHA-256 and byte total in `samples.py`; cached git-ignored under `weights/belfort/`, never vendored.
