#### Description

`stepfun-ai/GOT-OCR-2.0-hf` is the Transformers-native release of GOT-OCR 2.0 — "General OCR Theory: Towards OCR-2.0 via a Unified End-to-end Model" (Wei et al., arXiv:2409.01704; StepFun and collaborators) — contributed to the Hugging Face ecosystem by Yoni Gozlan and pinned here to revision `d3017ef2c2c1395888c8d635c5e0508bcb0ac78d` (the Hub's `main` on 2026-09-14). The snapshot `config.json` declares `GotOcr2ForConditionalGeneration` (`model_type` got_ocr2): a SAM-style ViT vision encoder over a 1024×1024 input (4,096 patch tokens, windowed attention with global-attention layers, eager attention only) whose features two stride-2 convolutions compress into **256 image tokens** projected into a 24-layer Qwen2-architecture text decoder (hidden size 1024, 16 heads, vocabulary 151,860 with a dedicated image token, tied input and output embeddings) — 560,528,640 parameters in the 1.12 GB bfloat16 `model.safetensors` (the config's `image_seq_length: 576` is not what the processor emits; the measured plain-mode prompt is 286 tokens: 256 image tokens plus the chat template). At inference the processor (`GotOcr2Processor`, `preprocessor_config.json`) resizes the image to 1024×1024 without preserving the aspect ratio, normalises with CLIP mean/std and wraps the image tokens in the snapshot's chat prompt for the requested mode; the decoder generates the text greedily until the `<|im_end|>` stop string or the budget. The upstream README documents plain-text, formatted (Markdown/LaTeX), multi-page, cropped-patch and region-guided (box/colour) modes; this pipeline exposes the first two. What this repository adds is packaging plus an adaptation contract: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `GotOcr2Pipeline.from_pretrained` (verified local loading with `trust_remote_code=False`, float32 on every device, the vision tower run one image at a time), `recognize` (input validation, the two modes, greedy decoding with the stop string under a caller-owned `max_new_tokens`, a `truncated` flag), `transcribe` (batched recognition — every plain-mode prompt has the same length, so a batch needs no padding), `character_error_rate`, `word_error_rate`, the `validate_inputs` and `evaluation_report` stage helpers, `samples.py` (the `{id, image, text}` line-record contract, the digest-pinned Belfort sample, image-disjoint splitting, a BYOD loader), `metrics.py` (micro and macro CER/WER, exact match, the empty-string and constant-transcript baselines), `evaluate` (corpus scoring), `adapt` (bounded fine-tuning of the last four decoder layers and the final norm — 51,401,728 parameters — with the causal language-model loss on cached frozen-prefix hidden states, transactional, validation-CER epoch selection), and `save_artifact` / `load_artifact` / `from_artifact` (a safetensors adapter with a manifest, verified before deserialising and overlaid on a freshly loaded base).

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is optical character recognition: input one image (`PIL.Image.Image`, any mode, converted to RGB), a mode (`plain` or `format`) and a token budget; output the recognised text, the number of tokens generated and whether the budget was exhausted. Envisioned applications are transcription of rendered or scanned document pages, screenshots and photographed signs or labels for indexing, search and downstream extraction; and, in `format` mode, first-pass conversion of pages with tables, formulas or structured headings into Markdown/LaTeX-style text for a human to check and render. The adaptation contract adds a second intended use: given 8..5,000 line images with transcripts from a document family the frozen model reads badly, measure its corpus CER and WER against two non-adapted baselines, fine-tune the last four decoder layers on a training split with validation-based epoch selection, evaluate on a line-disjoint test split, and ship the trained tensors as a verified adapter — the tutorial does this on French cursive council minutes. Within DIMER the pipeline is an inference component and a zero-configuration baseline for OCR with a bounded adaptation path, not a certified transcription engine for any specific document family, script or camera.

###### Primary Intended Users

Intended users are machine-learning engineers, document-processing developers, and data analysts integrating OCR into research prototypes, internal document tooling, or the DIMER workbench. A user is expected to understand that the output is *generated text* — it carries no per-character confidence, no boxes and no correctness signal, and the model produces text for any image, including one with none — that the token budget is theirs to set (a dense page can exceed 1,024 tokens and be reported `truncated`), that `format` mode adds markup that a plain transcript will count as errors, that the image is squashed to 1024×1024 so extreme aspect ratios and small type suffer, that the upstream training data is not disclosed in detail so the model's behaviour on scans, low resolution and non-Latin scripts is a distribution question this repository did not measure beyond one handwriting sample, that greedy decoding is reproducible on a fixed device and dtype but not across devices, that an uncapped error rate above 1.0 means the model is generating text the image does not carry, that a fine-tuned adapter reads the hand it was trained on and is not evidence about any other document family (the printed page the frozen model read exactly was still read exactly after the Belfort adaptation — one page, not a guarantee against forgetting), and that accuracy can only be measured on images with ground-truth transcripts they supply. Users who need layout, word boxes, multi-page handling, region-guided recognition, calibrated confidences or fine-tuning of the vision encoder are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no layout or reading-order output, no word or line boxes, no per-character confidence, no multi-page or cropped-patch modes, no region-guided (box/colour) recognition although the upstream model supports them, no rendering of formatted output (LaTeX, tables, charts, sheet music need external tools), no sampling or beam search, no abstention (the model cannot say "no text here"), and no fine-tuning of the vision encoder, the projector, the embeddings or the first twenty decoder layers.
2. **Input boundary:** `recognize` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 16384` px, areas above `MAX_IMAGE_PIXELS = 4096 * 4096`, modes not in `MODES`, and budgets outside `[1, MAX_NEW_TOKENS = 4096]` (`ValueError`/`TypeError`). Every image is resized to 1024×1024 with the aspect ratio discarded into 256 image tokens, so glyphs that are only a few pixels tall at that scale are unlikely to be read — a 128-px text line 9,000 px wide is accepted but arrives at the encoder as an eight-fold horizontal compression — and a page with more text than the budget allows is returned `truncated`. `validate_dataset` rejects records without `id`/`image`/`text`, ids outside `[A-Za-z0-9_.:-]{1,64}`, duplicate ids, images outside the ceilings, transcripts empty or over 512 characters after whitespace normalisation, and datasets outside 8..5,000 records; it checks structure only, never that a transcript matches its image.
3. **Input boundary:** the upstream paper describes training on synthetic and collected document, scene-text, formula, table, chart, molecular and sheet-music renders across English and Chinese; the snapshot README calls the model multilingual without enumerating scripts. Degraded scans, photographs with perspective and glare, dense multi-column layouts, right-to-left scripts and scripts absent from training fall outside what the upstream authors report and what this repository measured; results on them are undefined, not merely degraded. Handwriting is the one such family this repository measured — on one French cursive sample the frozen model's CER was 1.345 (worse than predicting nothing) — and the adapted number on that sample says nothing about other hands, languages or scripts. An image with no text still produces text (see §Risks and harms).
4. **Decision boundary:** not for autonomous decisions that act on transcribed values — invoice or contract processing feeding payments, clinical-record transcription, identity-document reading, regulatory filings — without a human comparing the text with the image, and a locally measured character error rate on the deployment's own labelled images. An adapter trained on one document family is not evidence about another: measure it there before relying on it.

#### Factors

###### Groups

This pipeline is not human-centric by design: it transcribes text in an image and never classifies, identifies or scores people. The upstream training data (per the paper: synthetic and collected document pages, scene text, formulas, tables, charts, molecular formulas and sheet music, in English and Chinese) contains no evaluation groups in the demographic sense, and neither the upstream authors nor this repository audited it for anything of the kind. What does vary is the text population: the model was trained predominantly on English and Chinese renders, so scripts, languages, fonts, handwriting styles, historical typesetting and document conventions outside that mix are the groups whose recognition accuracy is unknown, not known to be equal — and OCR error rates in the literature vary strongly by script and print quality. The adaptation sample is one such group — nineteenth-century French cursive from one municipal archive, transcribed by crowdsourcing (Tarride et al. 2023) — and within it the writers, decades and page conditions are not annotated, so the reported rates are averages over an unknown mix of hands. Where images carry personal data — medical records, HR files, identity documents, correspondence naming individuals — the pipeline's output makes that data machine-readable and searchable; the operator who processes such images is responsible for a fairness and privacy audit on their own image set, stratified by document family and script, before relying on the output or on an adapter trained on it.

###### Instrumentation

The upstream training "instrument" is largely a renderer — documents, formulas, tables and charts rendered to images with known text as the target, plus collected scene-text and page images — so crisp glyphs and known fonts dominate. Inference images arrive from whatever produced them — a PDF renderer at some DPI, a scanner, a phone camera with perspective and glare, a screenshot — and resolution, blur, compression, contrast, skew and font all change the visual evidence; the 1024×1024 resize discards resolution and distorts aspect on every image regardless of source. The Belfort lines are archival scans segmented automatically into lines (the dataset card notes segmentation errors), resized by the dataset authors to 128 px tall and stored as JPEG, so what the model sees after the square resize is a line stretched eight-fold vertically and compressed up to nine-fold horizontally — an instrument the adapted decoder learned to read but the frozen vision encoder was never trained on. The pipeline validates type and size only; it cannot detect a low-DPI render, a skewed photograph, a page cut mid-column, or an image with no text. The synthetic tutorial page (Pillow's bundled font, black on white, generous margins) is a best case: the frozen model transcribed it exactly, which bounds nothing about any real capture instrument.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0`, `numpy==2.5.3`, `pillow==11.3.0`, `huggingface-hub==0.36.2`, `pyarrow==25.0.1`; float32 on every device (the checkpoint's bfloat16 tensors are upcast at load; CUDA is used automatically when visible). The snapshot declares the slow image processor (transformers prints a `use_fast` notice); it is used as declared. The vision tower is eager attention over 4,096 patch tokens, so it runs one image at a time (`VISION_BATCH_SIZE = 1`) whatever the batch — on a 15 GB Tesla T4 a batch of eight images through it exhausted memory before that bound was added. Measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`) for the inference-only card: `verify_snapshot` on the 8-file, 1.14 GB snapshot 0.59 s; load 6.74 s; one 1000×520 rendered notice page 11.4 s in `plain` mode (154 tokens) and 11.8 s in `format` mode (157 tokens); a blank 1024×1024 image with a 64-token budget 4.7 s (8 tokens) — cost is dominated by autoregressive decoding and scales with the tokens a page needs. On a Tesla T4 (the adaptation build record) the frozen model transcribed the 140 test lines in batches of eight in 159 s, caching the frozen prefix for 600 training lines took 362 s and the six epochs with per-epoch validation scoring 924 s. Data environment: the model assumes an image of legible text in a script it was trained on; the synthetic page satisfies that assumption and is where the frozen behaviour holds. Scans, photographs, dense layouts and unfamiliar scripts violate it to degrees this repository did not measure; cursive French handwriting violates it to a measured degree (CER 1.345 frozen), and the pipeline reports no signal when an image does — nor when it contains no text at all.

#### Metrics

###### Performance Measures

Over a labelled line set the repository reports `ocr_metrics` (`metrics.py`): the **character error rate** and **word error rate** as micro averages — total Levenshtein edits (insertions, deletions, substitutions) over total reference characters or words, the corpus CER/WER of the handwriting-recognition literature, whitespace runs collapsed, case and punctuation kept, words lower-cased for WER — beside the macro (per-line mean) rates, the exact-match rate, the edit and character counts and the hypothesis length. Neither rate is capped, so a hypothesis longer than its reference pushes the rate above 1.0, which is the signal that the model generates text the image does not carry. `empty_baseline` (the empty string for every line, CER 1.0 by construction) and `constant_baseline` (the medoid training transcript for every line) answer through the same result shape, and `evaluate(records)` scores the model through `transcribe` in `plain` mode under `DEFAULT_LINE_MAX_NEW_TOKENS = 128`, returning the hypotheses with the rates and the truncation count. On the tutorial's 140-line Belfort test split (Tesla T4 build record, `SAMPLE_SEED` 42): empty 1.0 / 1.0 (CER / WER), constant `idem` 0.944 / 1.0, frozen 1.345 / 1.780 with hypotheses 1.6 times the reference length, adapted (layers 20–23 + norm, lr 5e-5, six epochs, epoch 4 kept) **0.759 / 1.017**, 3 lines exact. These are observations on one seeded split of one 800-line sample with no dispersion estimate, not a benchmark. Per image, the pipeline reports no accuracy measure: generated text carries no score, no probability and no correctness signal; `new_tokens` and `truncated` describe the generation, not its quality. The public `evaluation_report(result, reference_text=None)` stage returns the per-image report in machine-readable form: one entry for each error rate with the verdict `sample-sanity` when a reference transcript is supplied, or the verdict `not-measurable` naming the labelled set that would be required when none is. In `format` mode the markup the model adds (for example `\title{}` around a heading) counts as errors against a plain transcript, which the tutorial states rather than corrects. The upstream paper's numbers are upstream-reported and this pipeline does not reproduce or claim them.

###### Decision thresholds

No score threshold exists: the model generates tokens until it emits the stop string or the budget is exhausted, and nothing is filtered. The decision parameters are the **mode** — `plain` (the processor's default prompt) or `format` (the upstream `format=True` prompt; other upstream modes are refused) — and the **token budget** `max_new_tokens`, default `DEFAULT_MAX_NEW_TOKENS = 1024` for `recognize` (a practical single-page budget chosen by this repository; the rendered page needed 154) and `DEFAULT_LINE_MAX_NEW_TOKENS = 128` for the corpus stages (a transcribed line of up to 512 characters needs far fewer tokens; a runaway generation stops there and is counted as `truncated`), with ceiling `MAX_NEW_TOKENS = 4096` (the budget every example in the pinned README passes). A budget that is too small is reported, not hidden: `truncated` is true whenever `new_tokens` reaches it, and the caller should raise the budget and rerun. Decoding is greedy (`do_sample=False`) with `stop_strings="<|im_end|>"` passed with the processor's tokenizer, the README's setting; there is no repetition penalty, so a repetition loop runs to the budget. `adapt` selects its epoch on the lowest validation CER — a choice the caller can only change by editing the recipe — and its hyperparameters (`epochs=6`, `lr=5e-5`, `batch_size=8`, `GRAD_CLIP = 1.0`, no weight decay, no scheduler) are the configuration the build record found to move the held-out rate; the same recipe on the first 400 lines only (280 training lines) reached 1.302 CER on its own 80-line test split at lr 5e-5 and 1.040 at lr 1e-4 — both worse than the empty baseline — so the corpus size, not the rate, is what the default owes its result to. A deployment owns choosing the mode and the budget per document family, deciding whether a `truncated` page is retried or rejected, and re-measuring an adapter on its own labelled lines before relying on it.

###### Approaches to uncertainty and variability

Per image this repository reports no central metric value and therefore no dispersion: the smoke run records timings, token counts and two error rates on one rendered page, not accuracy. Run-to-run variability of inference comes only from floating-point kernel selection across CPU builds and accelerators; there is no sampling and no seed to set, so a fixed input on fixed hardware is repeatable, but because decoding is autoregressive a single differing token changes the rest of the sequence, and the CPU output need not match a CUDA output — nor a batched decode a single-image one, since the batch shape changes the kernels (the model-backed test asserts only that at least two of three lines agree). On the synthetic page the frozen model reproduced the 493-character transcript exactly in `plain` mode (character and word error rate 0.0) and scored 0.020 / 0.025 in `format` mode because of the `\title{}` markup — one observation on one clean page, not an estimate. The adaptation build record is one seeded split (`SAMPLE_SEED` 42, `adapt(seed=0)`) of one 800-line sample; the recipe probes that preceded it — the same scope on 280 training lines at lr 5e-5 for eight epochs (validation CER 1.36 → 0.71 at epoch 3, then 1.05 / 1.07 / 0.80 / 0.84 / 0.74 while the training loss fell to 0.03; test 1.302) and at lr 1e-4 (validation 0.674 at epoch 4; test 1.040), and a full-forward probe at 5e-5 on the build workstation that overfitted after its first epoch (validation CER 0.80 → 0.87 → 1.06 without selection) — are the only evidence of sensitivity, and they say the validation split is small enough that its curve is noisy and that 280 lines are too few, and no seed or split was repeated. Training four decoder layers is not bit-reproducible across GPUs, so a rerun a few hundredths off the record is the expected spread. A caller who needs an accuracy estimate must supply labelled images and compute error rates over many lines or bootstrap resamples themselves; a caller who needs a confidence signal per character has none from this model, before or after adaptation.

#### Ethical considerations and biases

No external ethics board, red-team, or population-specific clearance reviewed this repository or, to our knowledge, the upstream checkpoint; nothing below should be read as implying one.

###### Data

The snapshot README does not enumerate the training data; the paper describes a mixture of synthetic renders (documents, formulas, tables, charts, molecular formulas, sheet music) and collected document and scene-text images, in English and Chinese, with sources named only in aggregate. Collected document and scene images can contain personal data — names, addresses, licence plates, faces in the background — so personal data in the training corpus is not ruled out; it is not enumerated by the upstream authors and was not audited here. This repository distributes code, tests, and documentation; it does not distribute the 1,121,114,488-byte `model.safetensors` or the 18.7 MB `tokenizer.json`, which are staged locally under `weights/got-ocr-2.0-hf/` and git-ignored, and it ships no sample images — the tutorial page is rendered in code with fictitious names. The adaptation sample is fetched at run time from the Hugging Face Hub: the first eight row groups of the Belfort-line test shard (`Teklia/Belfort-line` at the immutable parquet-conversion revision `c4a74bbd39f2df314752e7e6026649a39d365cbb`, MIT; the minutes of the Belfort municipal council, nineteenth to twentieth century, transcribed by a crowdsourcing campaign — Tarride et al. 2023, Zenodo record 8041668), 800 line images pinned by SHA-256 and byte total per row group, read over HTTPS range requests, cached git-ignored under `weights/belfort/` and not redistributed. The minutes name real people — councillors, officials, residents whose affairs the council decided — who have been dead for a century or more; the transcripts are public archival records, and the adapter trained on them carries no more personal data than any language model trained on old text, but a deployment that trains on its own records must audit them. The operator must audit the images they submit for personal, proprietary, or otherwise restricted content; the pipeline performs no such check and will transcribe a medical record as readily as a meeting notice.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by this repository, the upstream authors, or any regulator. Foreseeable but unintended sensitive uses — transcribing clinical records or prescriptions, invoices or contracts for automated payment or compliance, identity documents for verification, legal filings for screening — would be admissible only with human comparison of the transcript against the image (the model can drop, alter or invent text with no signal), a locally measured character error rate on the deployment's own labelled images (and on the adapted model, if one is used), a documented mode and budget policy with `truncated` handling, and whatever regulatory clearance the domain requires.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 8 listed files' byte sizes and SHA-256 before any load; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, and the smoke run loaded and recognised with `HF_HUB_OFFLINE=1`. No pickle checkpoint exists at the pinned revision. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused; the import-boundary tests assert that a missing or tampered snapshot is refused before `torch` or `transformers` is imported. The sample corpus is pinned the same way: the shard's declared size and row count and every row group's SHA-256 and byte total are checked, and a cached row group that fails its digest is refetched rather than trusted.
- **Input integrity:** the public `validate_inputs(image, *, mode, max_new_tokens)` stage applies exactly the checks `recognize` applies (both route through one shared private checker) and returns an input manifest recording the schema, the ceilings, the observed input, the request and the verdict; `validate_image` rejects non-PIL inputs, sides outside 16–16,384 px and areas above 4096²; modes outside the two exposed forms, non-integer or boolean budgets, and budgets outside `[1, 4096]` are rejected; `recognize` raises on a malformed runner result; `validate_dataset` refuses malformed records before any model import.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; greedy decoding with no sampling; the stop string is a module constant; every result carries `model_id`, `model_revision`, the mode, the budget, `new_tokens`, `truncated`, the device, the dtype and whether an adapter is loaded; `adapt` seeds its shuffle and pins the cuDNN determinism flags for its duration.
- **Adaptation integrity:** `adapt` validates both splits before any tensor is built, trains only the last four decoder layers and the final norm with every other parameter's `requires_grad` false, computes the loss on cached frozen-prefix hidden states that equal the full model's (the cross-entropy is identical, taken only at transcript positions), restores the frozen weights and the previous adapter on any exception, and records the configuration and epoch history in the artifact; `from_artifact` re-verifies the base snapshot and checks the manifest's format, base identity and weight digest, the file size and SHA-256 and the exact tensor set **before** deserialising, refuses any tensor outside the last four decoder layers and the norm, and overlays the tensors onto a freshly loaded base rather than mutating a shared model; `split_dataset` de-duplicates by decoded pixels and `check_split_disjoint` asserts the splits share no image.
- **Refusals:** no download without the explicit flag, no free-form prompts or upstream modes beyond the two exposed, no sampling, no pickle deserialisation, no attempt to guess whether the image contains text or whether a transcript matches its image.
- No statistical mitigation (class balancing, subsampling) applies to the sample: the 800 lines are the first eight row groups of the shard as published, shuffled once with a fixed seed.

###### Risks and harms

- **Invented text on empty or unreadable input:** the model has no abstention — a blank image yielded `(0) = 1 +` in the smoke run, and on cursive it could not read the frozen model generated 1.6 times as many characters as the lines carry — so a photograph without text, a blank scan or an unreadable region produces a plausible fragment with no signal; downstream consumers that trust the string inherit the error silently.
- **Silent substitutions:** a wrong digit in an amount, a date or a reference number is still fluent text; only a character error rate on labelled images reveals the rate, and the tutorial's 0.0 on a rendered page bounds nothing.
- **Truncation and loops:** a dense page can exceed the budget (reported via `truncated`) and a repetition loop runs to the budget; a caller who ignores the flag ships a partial page.
- **Markup confusion:** `format` mode interleaves LaTeX/Markdown constructs with the text; a consumer expecting plain text mis-parses it.
- **Domain lock-in of an adapter:** four decoder layers fine-tuned on one hand read that hand and can move what they knew elsewhere — the one printed page the build record re-read after the Belfort adaptation was still read exactly (CER 0.000), which bounds nothing about other print; the harm falls on a deployment that reuses an adapter trained on another document family, or that assumes an adapted model still reads print.
- **Automation bias:** an exact transcript of a clean page invites trust that generated text has not earned on real captures.
- **Privacy exposure:** images containing personal or confidential text are transcribed without any content check and made searchable; an adapter trained on private lines is a 206 MB file that a deployment must handle as derived from that data.
- **Bias amplification:** any script, language, font or document family the English/Chinese render-heavy mixture under-represents is reproduced as uneven accuracy, undetected because no per-family evaluation exists; within the Belfort sample the hands and decades are not annotated, so an adapter that reads the common hand and not the rare one would go unnoticed by the corpus rate.
- **Resource use:** a 1.12 GB model, ~11 s per page on the reference CPU, and an adaptation path that needs a CUDA runtime with about 6.0 GB of memory; a page stream saturates a shared host quickly.

###### Use cases
